These are one-off workspace conversion tools, not Tent product compatibility code.

For 0.2.0 map layout cleanup, `remove-canvas-history.mjs` removes the retired canvas file and its history from SQLite format 1 or 2; see the [migration instructions](../../docs/MIGRATION.md#map-layout-from-020).

`convert-workspace.mjs` converted workspaces written before Node types became exact: a type such as `goal-decision` became `goal` with a `decision` tag, in the working documents and in the history under `.tent/.git`. Its header lists every rule it applies.

For the module-goal conversion, run `node --import tsx scripts/one-off/convert-module-goals.ts <workspace> <manifest.json>` to preview every before/after document. Each manifest entry names an observed Node ID and ETag, a reviewed purpose body, and a child prompt's name, tags and original rules body with relative links relocated one level down. Only active prompts declaring local directory or prefix coverage, or grouping qualifying goals in the final conversion batch, qualify. The tool retains identity, materials and existing children, then updates the goal and creates its rules child in one Core batch. Repeating an unchanged completed manifest writes nothing; stale inputs fail before applying. After reviewing the manifest and testing a copy, stop all writers and add `--apply`. This appends current document versions; it does not rewrite history or Card pins.

For removal of Node reconciliation records, stop all Tent writers and test an offline workspace copy, then run `node scripts/one-off/remove-node-records-history.mjs <workspaceRoot>` with the explicit workspace directory (the parent of `.tent`). Existing format 1 SQLite history must pass this conversion before opening with the current product. If the workspace still needs canvas cleanup, run `remove-canvas-history.mjs` first.

The record conversion edits a temporary database copy in `.tent/.git`, removes only the top-level `nodeRecords` event metadata member, the `records` and `unportable_records` tables, and explicit `Tent-Node-Record: ` lines in Git-import message audits. It validates all retained tables and SQLite integrity inside the transaction, vacuums the copy to remove retired free-page bytes, validates again, removes the disposable `.tent/.git/tent-material-cache/` directory, then atomically replaces the history file as format 2. Event IDs, sequence numbers, parents, times, other metadata, original Markdown audits, document blobs, changes, current membership, and working files (including `verified`) remain intact. It never opens or changes Node documents. Repeating the tool on a clean format 2 database opens it read-only and writes nothing. Unsupported formats, unsettled writes, journals, invalid databases, or unexpected retained-history changes fail without replacing the source.

That managed cache directory also holds the retired material fingerprints and structure text observations in `file-state.json` (`material:` keys), `structure-derived.bin`, and old prepared graph/Workspace observations in `stop-material-index.json`. The conversion removes the directory whole, including parse caches and temporary cache files; the current product rebuilds it from authoritative bytes with graph schema 14. Hook section fingerprints in `.tent/temp/section-fingerprints/` and turn/deletion baselines in `.tent/temp/turn-reviews/` are separate state and are preserved. A clean format 2 rerun preserves newly rebuilt caches and still writes nothing.
