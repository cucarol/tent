# Map an existing project

Give the code a small tree of module Nodes. A module is where later work records what the code cannot hold: rules, change flows, exceptions and decisions. Tent drafts the map from the code and checks it; you decide the modules and write what they hold.

1. Run `tent workspace scan --draft tent-draft.json`. It writes a `write-many` batch to that file and prints a short summary: each draft module with its `ref` and code file count, the guidance files, then lines to settle. Exit 1 means the summary has lines to settle this round; the file is written either way. A Workspace that already has Nodes gets no draft: fill its gaps as the last paragraph says.
2. Read the guidance files it lists, README first, then files such as AGENTS.md, CONTRIBUTING and design notes.
3. Edit `tent-draft.json` with your own editing tools, all in one pass:
   - **Names**: replace path-like names such as `src flask` with what the project calls that part. Keep every `ref`.
   - **Boundaries**: aim for about ten to fifteen modules that follow the project's own structure. Merge thin ones; split a large one only where its parts change apart. A dependency cycle stays inside one module, generated code goes with its source, and tests beside their code go with that code. A separate test directory is not a module: keep the draft's `Tests` Node with plain directory sources. When the files of one large directory import one another in a tangle, split it by dependency layer: files that import nothing above them form the lowest module (`tent workspace scan --json` lists `imports.edges`).
   - **Sources**: a module owns code through a directory such as `{"resource":"src/api/","track":"structure"}`, or in a flat directory through a file-name stem such as `src/flask/views*` with the same `track`; only such a source makes a Node a module. Paths start at the Workspace root. A module with child modules holds no source that covers them. Root code such as a package entry or `build.rs` goes as a plain file source in the module it belongs to; root configuration stays in `Setup`.
   - **Bodies**: write what grep cannot find: rules this code must keep, what else must change with it and how to verify, known exceptions, and decisions with their reasons. Take them from the guidance files and link those. Do not list files or entry points. Links are relative to the Node's own file: a module under the map lives at `.tent/Modules/<Name>/<Name>.md`, so it links the README as `../../../README.md`, and each level deeper adds one `../`. Link another item of the batch as `[Core](@core)`.
   - **Summary lines**: a `review` line names root code with no clear owner; add it to the module it belongs to. An issue line such as `module.oversized`, `deps.cycle` or `history.always-together` names module refs in `nodeIds` and says how to fix it; change the boundary, or keep an intended exception with one body line such as `allow:deps.cycle [Markdown](@markdown) shares link parsing`. If `history.always-together` and `module.oversized` contradict each other, follow history: merge the modules and allow the size. The `imports` count describes what Tent could not resolve in the code, not the map; leave it and mention it to the user.
4. Pipe the file into `tent node write-many --input-json -` once. On an error, fix only what it names and run it again. Delete `tent-draft.json` after it succeeds.
5. Run `tent workspace check-modules` and fix what it reports. After two rounds, stop and keep the remaining findings for the user.
6. Start `tent ui --idle-timeout 300` as a background command the user can see and stop. Give the user the address it prints, the module tree as `check-modules --json` lists it under `modules`, and any findings left.

To fill gaps in an existing map, map only what `check-modules` reports as uncovered and leave existing modules as they are. A map whose Nodes hold only plain directories has no modules yet: keep those Nodes, add `track` to the code directories that should be modules, leave a separate test directory plain, and rewrite their bodies as step 3 says.
